## 1. 一句话

同一个节奏，在不同程序里可以有不同含义：按下右键那一刻光标在哪个程序上，就用那个程序的含义；没有定义就用全局含义；到哪都要用的动作被“固定”，任何程序都不能改。

## 2. 设计决策（已确认）

| 决策 | 结论 | 理由 |
|---|---|---|
| 情境如何判定 | 按下触发键那一刻**光标下窗口**所属的程序（不是键盘焦点 / 前台窗口） | 盲操作时用户指着哪里，就是想操作哪里 |
| 同一节奏能否在不同程序有不同含义 | **能** | 最顺手的短节奏只有 6 个（1 位 2 个、2 位 4 个），每个程序都应该能用 |
| 如何避免“在某程序里丢掉必须的全局动作” | **固定**：系统级动作默认固定，任何程序不能改它的节奏 | 冲突只在“到哪都要用”的动作上才有害 |
| 被替换的全局含义如何临时找回 | **不提供**（已否决“停住 0.7 秒切回”和“按住 Shift”） | 有了固定后需求基本消失；隐藏交互违背简单原则；Shift 违背“不碰键盘” |
| “意图模型”（一个节奏只对应一个意图） | **否决** | 程序独有的功能会被迫使用更长的节奏，记忆负担更大 |
| 改了含义如何让用户知道 | 节奏地图 + 胶囊显示程序 + 前 5 次“新含义提醒” | 防止跨程序敲错 |
| 快捷键发到哪里 | 发送前**激活光标下的窗口** | 现状发到前台窗口，与“指着哪里操作哪里”不一致 |
| 排除列表与情境 | **排除优先**：光标在排除程序上时整段不拦截，也不走程序含义 | 与 v0.8「完全不拦截」一致，避免半拦截半执行 |
| 中键方向手势 vs 自动滚动 | **中键延迟决策**（与右键和弦同思路）：先拦截，再判定是单击补发、手势，还是静止按住后放行给系统 | 现状中键透传，浏览器/CAD 等在按下瞬间进入自动滚动或平移；放行保住了有意使用的自动滚动和平移 |
| 执行后键盘焦点 | **留在目标窗口**，不切回原窗口 | 指着哪里就是要在哪里继续操作（例如新建标签页后直接输入网址）；与鼠标点一下窗口的结果一致 |
| 界面里的“当前程序” | 指令库、仪表盘、状态栏用**最近输入的程序**，不用光标实时位置 | 看 PulseMouse 窗口时光标总在 PulseMouse 上，实时位置没有意义 |

## 3. 术语

| 术语 | 含义 |
|---|---|
| 全局含义 | `Scope == ""` 的指令；所有非桌面情境的默认含义 |
| 程序含义 | `Scope` 为某个进程名的指令；只在情境等于该进程名时生效 |
| 替换 | 程序含义使用了某条非固定全局指令的节奏；在该程序中取代全局含义 |
| 专属 | 程序含义使用的节奏在全局没有指令 |
| 固定 | 全局指令的属性；固定的节奏在所有程序中都是这条全局含义，不能被程序含义使用 |
| 程序列表 | `ContextApps`；决定节奏地图有哪些列，独立于指令保存 |
| 情境 | 本次输入所属的上下文，在按下触发键时确定。普通窗口 = 进程名；**桌面情境** = 哨兵值（见 5.1），不是 `explorer` |
| 新含义提醒 | 替换型程序含义的前 5 次成功执行，胶囊额外提示“这里是新含义 · 全局是什么” |
| 最近输入的程序 | 最近一次按下触发键时的情境（不含 PulseMouse 自身和桌面），只保存在内存中；启动后还没有输入时为空 |
| 情境快照 | 按下触发键时记录的 根窗口句柄 + 进程 Id + 进程名 + 是否桌面；执行前用它复核目标窗口 |

## 5. 功能规格

### 5.1 情境判定

1. 在触发键按下的那一刻确定情境，本次输入期间不再改变（松开前把光标移到别的窗口不影响）。
   - 右键和弦：右键按下时。
   - 侧键直敲：侧键第一次按下时。
   - 中键长按：中键按下时。
2. 取光标位置的窗口：`WindowFromPoint` → `GetAncestor(GA_ROOT)`，记录**情境快照**：根窗口句柄、进程 Id、进程名（规则同 `MouseHook.NormalizeAppName`：小写、去掉 `.exe`）、是否桌面。
3. **桌面情境（哨兵）**：窗口类为 `Progman`、`WorkerW`、`Shell_TrayWnd`、`Shell_SecondaryTrayWnd` 时，情境记为哨兵值 `__desktop__`（内部常量；UI 显示「桌面」）。
   - 解析时 `__desktop__` **只使用全局含义**，永不匹配任何 `Scope`（包括 `Scope == "explorer"`）。
   - 资源管理器**文件窗口**（同为 `explorer.exe`，但不是上述桌面/任务栏类）情境为 `explorer`，可有程序含义。
4. 情境无法取得（窗口已销毁、无权限读取进程名）时按 `__desktop__` 处理。
5. **排除优先于情境**：若光标下程序在「排除的程序」列表中，行为与 v0.8 相同——**完全不拦截**（不进入节奏、不解析、不执行）。排除列表优先于「按程序切换含义」。
6. “按程序切换含义”关闭时，任何情境都只用全局含义（程序含义保留不删）。
7. 方向手势不使用情境（v0.9 不做按程序区分手势）。
8. 每次取得情境后，若不是 PulseMouse 自身也不是桌面，更新“最近输入的程序”。

### 5.2 解析规则

```
Resolve(pattern, context):
  g = 全局指令中 Pattern == pattern 的那条
  if g != null && g.Pinned           → g
  if 按程序切换开启 && context != "__desktop__":
      a = 作用范围 == context 且 Pattern == pattern 的那条
      if a != null                   → a
  if g != null                       → g
  → 未匹配
```

- 解析放在 Core，纯函数，可单测。
- 未匹配时胶囊与日志写明程序：“Chrome 中没有 ·—·”。
- 犹豫提示与仪表盘候选使用同一套解析：列出 `Resolve` 后可达的结果，按节奏长度、再按 `·` 在 `—` 前排序，最多 6 条，其余显示“另有 N 条”。

### 5.3 固定

1. 只有全局指令有“固定”属性；程序含义忽略 `Pinned`。
2. **`ActionKind.Workflow` 与 `ActionKind.Repeat` 只能是全局**，且默认固定。编辑栏不允许把它们的作用范围改成「指定程序」；若导入配置中出现带 Scope 的工作流/重复，迁移或导入时强制 `Scope=""` 并固定。
3. 新建或修改全局指令时，**未手动改过固定开关**的，按下表自动设定：

| 自动固定 | 不固定 |
|---|---|
| 类型为 程序 / 文件夹 / 网址 / 工作流 / 重复上一次 | 其他快捷键（复制、粘贴、撤销、关闭标签、刷新等作用在程序内部的） |
| 快捷键为：`Alt+Tab`、`Win+Tab`、`Win+D`、`Win+E`、`Win+L`、`Shift+Win+S`（含 `Win+Shift+S` 写法）、`VolumeMute`、`VolumeUp`、`VolumeDown`、`MediaPlayPause`、`MediaNextTrack`、`MediaPrevTrack` | |

4. 用户可在编辑栏手动开关“固定：在所有程序中保持不变”，之后不再自动改。
   - **允许取消**系统级快捷键的固定（进阶行为）：取消后程序含义可以占用该节奏。
   - **打开固定**时，若已有程序含义使用该节奏，阻止保存并提示：“Excel 中是「重复上一步」；要固定需先移除这些程序含义”。
5. 删除一条固定的全局指令后，该节奏在各程序中解锁。

### 5.4 冲突与校验

编辑栏节奏输入下方的提示，按优先级：

| 情况 | 级别 | 文案示例 | 能否保存 |
|---|---|---|---|
| 未输入 | 提示 | 点击添加短按 · 或长按 —，最多 5 位 | 否 |
| 工作流 / 重复上一次却选了指定程序 | 错误 | 工作流与「重复上一次」只能是全局 | 否 |
| 同一程序已有该节奏 | 错误 | Chrome 中这个节奏已经是「刷新」 | 否，给出 3 个推荐 |
| 程序含义使用固定节奏 | 错误 | 「切换窗口」已固定，在所有程序中保持不变 | 否，给出 3 个推荐 |
| 程序含义替换非固定全局 | 警告 | 在 Chrome 中替换全局「复制」；其他程序不受影响 | 能 |
| 程序含义使用空闲节奏 | 通过 | Chrome 中可用；其他程序里这个节奏没有含义 | 能 |
| 全局已有该节奏 | 错误 | 已被全局「复制」占用 | 否，给出 3 个推荐 |
| 全局节奏在某些程序中被替换 | 通过 | 可用；Excel 中是「重复上一步」 | 能 |

- **名称不必全局唯一**：不同程序（或与全局）可以同名；匹配只看节奏 + 作用范围。
- **推荐空闲节奏**：按 1 位 → **5 位**、同长度 `·` 优先的顺序，取前 3 个满足“全局未使用，且（程序含义时）该程序未使用”的节奏，点击即填入。（效果图演示里空闲节奏只列到 4 位；实现按 5 位。）
- **修改全局指令的节奏**时，若旧节奏在某些程序中被替换，保存时提示：“Excel 中的「重复上一步」仍在 —，它会变成 Excel 专属”。程序含义绑定在节奏上，不跟随全局指令移动。
- **修改作用范围（全局 ↔ 程序，或程序 A ↔ 程序 B）**：允许；保存前按新 Scope 重跑本表校验；指令 `Id` 与历史统计保留；若从「替换型」变为「专属型」或改为全局，将 `RemindLeft` 置 0；若改为替换型且原先为 0，置为 5。
- 其余校验（名称必填、目标合法、最多 5 位）保持现状。

### 5.5 程序管理

- **程序列表单独保存**（`ContextApps`），不从指令推算。程序最后一条含义被移除后，列仍保留。
- **添加程序**：弹窗列出
  - **最近输入的程序**置顶（若有且未添加），标注“刚刚用过”；
  - 当前运行中的有窗口程序（`EnumWindows` 取可见、无 owner 的顶层窗口所属进程；排除 PulseMouse 自身和系统进程）与本次运行中出现过的情境程序，标注“运行中 / 最近使用 / 已添加”；
  - “拾取窗口”：3 秒内把光标移到目标窗口上，读取其进程名；
  - “浏览 .exe…”：选择可执行文件，取文件名作为进程名。
  - **不提供**“添加光标所在程序”按钮：点按钮时光标就在 PulseMouse 窗口上。
  - 显示名默认取可执行文件的文件描述（`FileVersionInfo.FileDescription`），取不到用进程名。图标取可执行文件图标。
- **移除程序**：节奏地图列标题右侧 “×” 与列表视图分组标题的“移除”。弹出确认框，逐条列出将删除的含义及删除后的结果（“→ 全局「关闭标签页」”或“→ 无含义”）。确认后删除该程序的全部含义并移出程序列表。
- 编辑栏“指定程序”的候选：程序列表 + 最近输入的程序 + “拾取窗口”。保存程序含义时自动把该程序加入程序列表。

### 5.6 执行：激活目标窗口

- 仅对**快捷键**动作生效（程序、文件夹、网址、工作流不受影响）。
- 开关“发送快捷键前激活光标下的窗口”开启（默认）且情境不是桌面时：
  1. **复核目标**：情境快照里的窗口仍存在（`IsWindow`），且所属进程 Id 与快照一致；否则不发送，失败“目标窗口已关闭”。
  2. 若情境窗口已是前台，直接发送；
  3. 否则激活情境根窗口（`SetForegroundWindow`；被前台锁拒绝时使用 `AttachThreadInput` 或补发一次 Alt 的常规做法），等待前台切换完成（最多约 150 ms）；
  4. **发送前再确认一次**前台就是该窗口，再发送；
  5. 激活失败：不发送，胶囊失败态“无法切换到 Chrome 窗口”，日志写明原因，并计入当日 `ActivationFailed`（诊断页显示“今日激活失败 N 次”，用于判断激活策略是否可靠）。
- **执行后焦点留在目标窗口**，不切回原来的前台窗口（见 §2）。
- 情境窗口以管理员身份运行而 PulseMouse 不是：右键和弦本来就放行（现状）；侧键与中键模式下胶囊提示“目标窗口以管理员身份运行，无法发送快捷键”，不静默失败。
- 关闭开关时恢复现状行为（发送给当前前台窗口）。
- **指令库「测试」按钮**（快捷键）：
  - 激活开关**开**：与真实执行相同——先激活光标下窗口再发送（光标在桌面或激活失败则 Toast 说明并不发送）。
  - 激活开关**关**：发到当前前台（可能是 PulseMouse 自身），Toast 提示“未开启「发送前激活」，快捷键会发到前台窗口”。

### 5.7 重复上一次（新动作类型）

- `ActionKind.Repeat = 5`，追加在现有枚举之后，旧值不变。
- 无目标字段；**只能全局**；默认固定（见 5.3）。
- 记录“上一次”：最近一次**成功执行**的节奏指令或手势，记下动作、情境进程名与窗口句柄。工作流和“重复上一次”本身不记录。
- 执行：
  - 上一次是快捷键：按 5.6 的步骤复核并激活原窗口后发送（**始终**激活，不依赖「发送快捷键前激活」开关，因为目标是“当时那扇窗”）；原窗口已最小化则先还原；原窗口已关闭或进程 Id 不同则失败“原窗口已关闭”。
  - 其他类型：直接再执行一次。
  - 没有可重复的动作：失败“还没有可重复的动作”。
- 胶囊与最近执行显示“重复：粘贴”。统计同时计入“重复上一次”和被重复的指令。
- “上一次”只保存在内存中，不写入配置。

### 5.8 新含义提醒

- 替换型程序含义新建（含从模板添加）时 `RemindLeft = 5`；专属型为 0。
- 该含义每次成功执行后减 1，至 0 停止提醒。
- 提醒期间胶囊边框与情境行为琥珀色，情境行文案：“Excel 中 — 是新含义 · 全局是「关闭标签页」”，完成态停留约 2.2 s（普通 1.4 s）。
- 设置“新含义提醒”关闭时不显示，计数不变。

### 5.10 使用热度

- **计数**：每条指令按 **Id** 记入当日 `CommandsToday`；日终滚入 `History`（结构沿用，键改为 Id）。
- **7 日柱状图**：对最近 7 个自然日，从 `History` + 今日 `CommandsToday` 按 Id 取值拼成 7 根柱；无记录的天为 0。无使用显示“7 天未用”。
- **上次**：`LastUsed`（ISO）与 `LastContext`（情境进程名或 `__desktop__`）写在指令上，编辑栏显示“上次 10:02 在 Chrome”。
- 列表行、节奏地图格子右上角显示 7 日合计。
- 热度只用于展示，v0.9 不做“长期不用建议删除”之类的提示。

| 名称（zh / en） | 默认节奏 | 快捷键 | 推荐 |
|---|---|---|---|

| 刷新 / Refresh | `···` | F5 | 是 |
| 重新打开标签页 / Reopen tab | `·——` | Ctrl+Shift+T | 是 |
| 前进 / Forward | `—·` | Alt+Right | 否（可选） |

| 状态 | 判定 | 默认 |
|---|---|---|
| 已添加 | 该程序已有**同名且同节奏**的含义 | 禁用 |

| ≥ 900 px（最大化 / 宽屏） | **双栏**：整体最大宽 1100，水平居中；左右两列等宽，列间距 18 |

**验收：**

### 5.14 语言（界面壳全量中英）

**现状问题：** 设置里可选 English，但 `Loc.cs` 只覆盖导航、页标题、类型标签与状态栏；五个页面的按钮、分组、表单、Toast、胶囊、日志等仍是硬编码中文，切换后“看起来还是中文”。

**目标：** English 下**全部界面壳**为英文；用户自己起的名字与配置值保持原样。

| 类别 | 是否翻译 | 例子 |
|---|---|---|
| 界面壳 | **是** | 导航、页眉、设置分组与行文案、按钮、空状态、图例、冲突提示、模板库 UI、Toast、工作流确认框、胶囊情境行、犹豫提示标题与标注、仪表盘统计卡与说明 |
| 诊断日志 | **新行是**；历史行否 | 新写入的日志用当前语言；已存在的行不回翻 |
| v0.9 新文案 | **是**（必须进 Loc，禁止再写死中文） | 「中的含义」「固定」「替换全局」「新含义提醒」「沿用 · X」「可按程序改」等 |
| 用户数据 | **否** | 指令名称、工作流名称、排除程序列表、AI URL、自定义路径 |
| 程序显示名 | 优先系统/文件描述；没有则进程名 | `FileVersionInfo.FileDescription` → 进程名；不强制英文化 |
| 快捷键与技术标识 | **否** | `Ctrl+C`、`Alt+Tab`、Hook、SchemaVersion |

**不做：**

- 不自动改写已有配置里的指令名（含自用周 6 条与默认示例）。
- 不因语言切换重建默认指令集。
- 不做第三语言；不从网络下载语言包；不引入 `.resx` / WPF 资源字典。

**技术：** 继续扩展现有 `Loc.cs`（`T(zh, en)` 成对字符串）。`ActionKind.Repeat` 等新类型标签一并加入 `Loc.Kind`。

**切换行为：**

1. 设置 › 通用 › 语言：中文 / English（说明：「切换全部界面文案；你起的指令名称保持不变。」）。
2. 写入 `UiLanguage`（`zh-CN` / `en-US`），`ApplySettings` 设置 `Loc.English`，调用现有 `Relocalize()`。
3. 各页 `Relocalize()` **必须刷新本页全部壳文案**（不只页眉）：设置页分组与行、指令库工具栏/图例/空状态、仪表盘统计卡标签、手势/工作流页按钮等。
4. 胶囊与犹豫提示、Toast、工作流确认框、状态栏在下一次显示时使用当前语言（进行中的胶囊可立即刷新文案）。
5. 诊断日志：新写入用当前语言；历史行不回写翻译。日志中嵌入的用户指令名保持原文。

**模板库：** 见 5.11（中英默认名；添加时按当前语言写入）。

**验收：**

- 切到 English 后：导航、五个页面可见壳、设置全部行、胶囊情境行、Toast、**新产生的**诊断日志均为英文；指令列表里用户名（如「复制」「打开飞书」）仍为原样；切换前的旧日志行可仍为中文。
- 切回中文，壳恢复中文，用户名不变。
- 重启后语言偏好保持。
- 新增 Context Pulse 相关提示在两种语言下都有对应文案，无中英混杂的壳字符串。

### 5.16 方向手势 · 中键延迟决策

**现状问题：** 方向手势为「按住中键拖动」；钩子对中键**始终透传**。浏览器在中键**按下**时进入自动滚动，CAD/PDF 等常把中键当平移。结果往往是手势执行了，页面也在滚。仅靠「最小移动距离」无法避免按下瞬间的透传。

**原则：** 与右键和弦相同——**先拦截，再判定**是原生单击、PulseMouse 手势、中键节奏武装，还是放行给系统。不引入键盘修饰键。

一句话：**短点 = 系统中键；按下就拖 = 手势；静止按住一会儿 = 系统中键按住（自动滚动、平移照常）。**

#### 何时拦截

在以下条件同时满足时，拦截中键（`WH_MOUSE_LL` 吃掉 down/up，必要时也抑制该次按住期间的多余透传）：

1. 引擎已启用；
2. 「启用方向手势」为开，**或** 输入方式为「中键长按 + 左键」；
3. 光标下窗口未命中排除列表 / 全屏暂停 / 管理员绕过（规则同现有 `TargetInspector.Bypass`）。

否则中键完全透传（与关手势、排除程序时一致）。

适用输入方式：默认自动（未检测到侧键 = 右键和弦）、显式右键和弦、经典中键模式。自动模式已改用侧键敲节奏时：若手势仍开启，中键仍走本条延迟决策（侧键不管中键）。

#### 判定

“静止”指离按下位置不超过 12 px（与现有 `MiddleActivation.MovementTolerancePx` 相同）。

| 时机 | 条件 | 行为 |
|---|---|---|
| 按住期间 | 移动距离 ≥「最小移动距离」（默认 75 px） | 进入手势；松开时识别上下左右并执行；**不**补发中键；胶囊可轻提示「↑ 手势」等 |
| 按住期间（钩子线程现有 40 ms 定时检查） | 自动/和弦模式，一直静止，按住 ≥ **静止放行时长**（默认 **600 ms**） | **放行**：在按下位置补发中键按下，之后的移动与松开全部透传，本次不再识别手势。浏览器自动滚动、CAD/3D 平移照常可用。做法同右键和弦的“按住不动补发按下” |
| 松开时 | 静止，按住 &lt; 单击上限（默认 **400 ms**，可配置 200–800） | **补发**一次中键单击（`SendInput`，带自身注入标记，忽略回声），保留开新标签、中键粘贴等系统行为 |
| 松开时 | 静止，按住 ≥ 中键激活时长（现有 `MiddleHoldMs`，默认 550），且为**中键长按 + 左键**模式 | 进入节奏武装（现状 `MiddleActivation`）；**不**补发中键。此模式下没有静止放行 |
| 松开时 | 其余情况：动过但没到手势距离；或按住时长落在单击上限与放行 / 激活时长之间 | 什么都不做（视为取消） |

- 拖动手势优先：只要达到手势距离，一律走手势，即使按住时间很长。
- 静止放行之后，本次按住期间不再判定手势或武装。
- **按下就拖**一律是手势。CAD、Blender、Figma 等习惯“按下中键就拖动平移”的程序，平移会变成手势：在手势页提示把这些程序加入“排除的程序”（排除后中键完全原生）；或者先静止按住 0.6 秒再拖。

#### 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `GesturesEnabled` | true | 现状已有；关则不拦截中键（除非处于中键节奏模式，该模式仍须拦截以免自动滚动） |
| `GestureMinDistancePx` | 75 | 现状已有 |
| `MiddleClickMaxMs` | 400 | **新增**：静止且短于此时长 → 补发单击（200–800） |
| `MiddlePassThroughMs` | 600 | **新增**：自动/和弦模式下静止按住达到此时长 → 放行给系统（400–1500；0 = 关闭放行，静止长按视为取消）。必须大于 `MiddleClickMaxMs`，保存时自动校正 |
| `PreserveMiddleClick` | true | **新增**：为 false 时，短点也不补发（进阶；中键单击对系统失效） |

迁移：旧配置补上 `MiddleClickMaxMs=400`、`MiddlePassThroughMs=600`、`PreserveMiddleClick=true`。

#### 界面

- 手势页中心文案：「按住中键拖动」；说明改为：「短点仍是系统中键（开链接等）；按下就拖触发手势，不会带动页面滚动；静止按住一会儿再拖，仍是系统的自动滚动或平移。」
- 手势页“中键延迟决策”卡片：单击上限、静止放行时长、「保留中键单击」开关（默认开），以及一行提示：「CAD、Blender、Figma 等用中键拖动平移的程序，建议加入“排除的程序”」，点击跳到设置 › 鼠标拦截。
- `Loc` 页描述同步中英（不再写「页面与 v0.8 相同」）。

#### 实现要点

- `MouseHook`：手势/中键模式路径不再对中键 down 直接 `CallNextHookEx`；补发复用现有注入标记与回声忽略。
- 补发失败（注入被拦）：胶囊/日志提示；不重试死循环。
- 排除列表、全屏暂停、管理员窗口：与现状一致，整段不拦截。

#### 验收

- Chrome / Edge 页面：中键拖动手势执行对应动作，**页面不进入自动滚动**。
- 同一页面短点中键：仍能开新标签（或系统默认中键行为）。
- 关「启用方向手势」且非中键节奏模式：中键行为与未安装 PulseMouse 时一致。
- 同一页面静止按住中键约 0.6 秒：进入浏览器自动滚动，之后移动不触发手势。
- 经典中键模式：静止长按武装后可用左键敲节奏，过程中无自动滚动。
- PDF 阅读器 / CAD 抽测：按下就拖是手势（预期行为）；静止按住后拖动是原生平移；把程序加入排除列表后中键完全原生。
- 右键和弦、侧键输入在 M1 前后行为一致（回归检查）。

### 7.1 执行链拆分（防止 `PulseController` 继续膨胀）

`PulseController.cs` 现在已有 737 行。v0.9 新增的情境、解析、激活、重复、提醒、统计**不直接写进它**，而是走一条固定的执行链：

```
情境快照 ──► ContextResolver ──► ExecutionRequest ──► CommandExecutor ──► ExecutionResult
（Windows）    （Core，纯函数）     （不可变）            （激活 + 执行）       ──► 胶囊 / 统计 / 提醒 / 日志 / 活动流
```

| 类型 | 位置 | 内容 |
|---|---|---|
| `ContextSnapshot` | Core | 根窗口句柄、进程 Id、进程名、是否桌面 |
| `ExecutionRequest` | Core | 来源（节奏 / 手势 / 重复 / 测试按钮）、节奏、情境快照、解析出的指令、含义来源（程序 / 全局 / 固定）、是否需要激活 |
| `ExecutionResult` | Core | 成功与否、失败原因（枚举：未匹配、窗口已关闭、激活失败、管理员窗口、动作失败、没有可重复的动作）、实际执行的指令、是否处于新含义提醒 |
| `CommandExecutor` | App 服务层 | 收请求 → 按 5.6 复核与激活 → 调 `ActionRunner` → 返回结果；不碰界面 |
| `ExecutionEffects` | App 服务层 | 收结果 → 胶囊、按 Id 统计与热度、`RemindLeft` 递减、`LastUsed` / `LastContext`、“上一次”、活动流、日志、激活失败计数 |

- `PulseController` 只负责把钩子事件接到这条链上，以及设置和保存。
- 胶囊、统计、日志只读 `ExecutionResult`，不各自重新解析或判断失败原因，保证三者口径一致。
- `ExecutionRequest` / `ExecutionResult` 是纯数据，Core 冒烟测试可以直接构造。

## 9. 已知限制（v0.9 接受）

- 网页应用与浏览器共用进程（例如网页版飞书与 Chrome 都是 `chrome.exe`），无法区分。后续可考虑按窗口标题细分。
- UWP 应用的进程可能是 `ApplicationFrameHost`，需要取子窗口的真实进程；若取不到，按 `ApplicationFrameHost` 处理并在添加程序时提示。
- 方向手势仍不按程序区分含义（与节奏的 Context Pulse 独立）。
- 激活窗口可能被某些全屏程序或系统前台锁阻止，此时失败提示而不是发错窗口。
- 用户可手动取消系统快捷键的固定，从而允许程序占用 `Alt+Tab` 等节奏——视为进阶风险，不额外二次确认。
- 中键补发依赖 `SendInput`；若注入被环境拦截，短点无法还原系统中键（与右键和弦相同限制）。
- “按下中键就拖动平移”的程序（CAD、Blender、Figma 等）在开启手势时平移会变成手势；需要加入排除列表，或改成静止按住后再拖。v0.9 不做“只对某些程序关闭手势”。
- 执行快捷键后焦点留在目标窗口；习惯“光标指着别处、键盘继续在原窗口打字”的用户需要适应。
