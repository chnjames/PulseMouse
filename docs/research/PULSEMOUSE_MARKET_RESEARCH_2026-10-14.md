# PulseMouse 市场与竞品研究

> 调研日期：2026-10-14  
> 范围：Windows 桌面效率工具、鼠标手势/轮盘、启动器与快捷触发器。竞品能力只采用官方产品页或官方文档；产品现状以仓库 `README.md`、`docs/PRODUCT_ROADMAP.md` 和源码说明为准。

## 执行摘要

PulseMouse 的创意**有价值，但不是因为它能“自动化更多事情”**。程序、文件、网址、快捷键、文本和工作流执行已经是高度成熟的市场，Quicker、Raycast、PowerToys 和 Logitech 都拥有更广的动作集合或生态。PulseMouse 值得继续的理由，是它有机会把最常用的 3–8 个动作变成一种不看屏幕、不移动光标、几百毫秒内完成的肌肉记忆。

因此，最合适的产品定义不是“又一个效率工具”，而是：

> **鼠标上的快捷键层：保持光标不动，敲一个节奏，立即执行此刻最常用的动作。**

这一定义成立有三个硬条件：

1. 触发不能破坏右键、中键、前进/后退等鼠标原生行为；
2. 熟练用户从开始触发到提交应接近 500 ms，且不必等待固定超时；
3. 新用户不需要先记一套抽象编码，能从 3 个有意义的节奏开始，并在遗忘时得到提示。

在这三个条件得到真实用户验证前，不建议继续投入 AI、复杂工作流编辑器或动作市场。它们会把项目带入强敌最密集、而本项目没有优势的区域。

## 1. 竞争格局

### 1.1 Quicker：最直接的替代品

Quicker 已把动作面板、轮盘菜单、鼠标手势、左键辅助都组织在“场景”下；场景可按当前应用切换，同一手势能在不同程序中执行不同动作。[官方场景与动作管理文档](https://getquicker.net/KC/Manual/Doc/profiles)

其手势文档明确描述了 PulseMouse 同样会遇到的学习问题：手势直接、迅速、数量可扩展，但需要记忆；官方建议少量逐步添加，并让形状与动作含义有关。Quicker 还提供“停住后显示最匹配手势”的提示机制。[官方鼠标手势文档](https://getquicker.net/kc/manual/doc/gestures)

动作广度也不是 PulseMouse 短期能正面竞争的：Quicker 的简单动作已经覆盖模拟按键、运行程序/文件、网址、发送文本与脚本；轮盘/热键还支持多步骤输入和调用复杂 Quicker 动作。[官方简单动作类型](https://getquicker.net/kc/manual/doc/simple-actions) · [官方快速操作说明](https://getquicker.net/kc/manual/doc/quick-actions)

**启示**：PulseMouse 不应复制 Quicker 的动作平台。可将 Quicker 动作视为下游，把自己做成更快的盲操作触发器；同时借鉴“逐步添加、语义关联、犹豫即提示”。

### 1.2 Logitech Actions Ring：强可视化、硬件绑定

Logitech 的 Actions Ring 是一个八气泡屏幕浮层，可由兼容 MX 设备的可编程按键唤出；用户移动光标并点击气泡执行动作。它支持系统动作、应用插件、Smart Actions，以及文件夹中的二级气泡。[官方 Actions Ring 文档](https://support.logi.com/hc/en-ca/articles/17844647906967-Actions-Ring)

**启示**：Actions Ring 解决的是“看得见、可发现、无需记忆”。PulseMouse 不应做另一个轮盘，而应强调其反面优势：无需把光标移到菜单、不遮挡工作内容、熟练后无需看屏幕，并且不绑定某一硬件品牌。

### 1.3 Raycast / PowerToys：键盘优先的一站式入口

Raycast for Windows 官方将产品定义为统一启动器，覆盖应用、文件、剪贴板、文本片段、网址、AI 和扩展，并允许给命令配置 Hotkey/Alias。[Windows 产品页](https://www.raycast.com/windows) · [官方 Quickstart](https://manual.raycast.com/quickstart) · [官方扩展说明](https://manual.raycast.com/extensions)

PowerToys 的 Command Palette 同样能启动应用、命令、文件搜索与系统工具，并明确是 keyboard-first 工作流；Keyboard Manager 支持按键、快捷键和文本序列映射。[Command Palette 官方文档](https://learn.microsoft.com/en-us/windows/powertoys/command-palette/overview) · [Keyboard Manager 官方文档](https://learn.microsoft.com/en-gb/windows/powertoys/keyboard-manager)

**启示**：凡是需要搜索、输入参数、浏览结果的任务，键盘启动器更合适。PulseMouse 应只服务“无需参数、答案唯一、频率很高”的动作，并把“手没有离开鼠标”作为使用前提。

### 1.4 市场空位

竞品已经很好地覆盖三种模式：

| 模式 | 代表 | 用户代价 |
|---|---|---|
| 搜索后执行 | Raycast、PowerToys | 手回键盘、输入、选择结果 |
| 看菜单后执行 | Quicker 面板、Actions Ring | 唤出、观察、移动光标、点击 |
| 画轨迹后执行 | Quicker 手势 | 移动光标、记图形，可能干扰当前位置 |

PulseMouse 可以专注第四种模式：**光标不动的短节奏输入**。它的上限不是“无限动作”，而是“把少量动作练成反射”。这个限制应成为产品设计原则，而不是被功能堆叠掩盖。

## 2. 最有价值的使用场景

### 场景 A：鼠标主导工作中的高频局部动作（首选）

适合设计、表格、浏览、视频审阅等手长期停留在鼠标上的工作。动作示例：撤销/重做、复制当前对象链接、窗口置顶、静音、截图、切换某个固定面板。

成立条件：动作每天出现多次、结果唯一、不需选择参数；按应用切换同一节奏的含义，能显著减少记忆数量。

### 场景 B：会议与演示中的“隐形控制”（首选）

静音/解除静音、摄像头开关、下一页、开始/停止录制、显示桌面。用户不希望打开菜单或把光标移离内容，盲操作优势最容易被感知，也容易用短视频演示。

风险：必须有强状态反馈，避免“不知道当前是静音还是取消静音”；全屏与演示模式不能简单地一律暂停，而应提供明确的应用级白名单。

### 场景 C：全局即时动作（次选）

锁屏、媒体控制、音量、启动固定应用、打开固定工作区、运行已有 Quicker/AutoHotkey 脚本。适合作为默认模板，但其中很多动作也能被键盘媒体键或启动器完成，差异来自“手正在鼠标上”。

### 场景 D：单开关/运动障碍辅助（独立赛道，暂不并入主线）

节奏编码天然有单一输入通道的潜力，但无障碍产品需要扫描输入、校准、容错、文本输入、可访问 UI 和长期可靠性，验证标准远高于普通效率工具。它可能有社会价值，但应作为独立研究项目，不能仅用现有鼠标钩子加一个标签就宣称可用。

### 不优先的场景

- 低频动作：用户在需要时已经忘记节奏；
- 需要搜索、参数或结果选择的动作：启动器更自然；
- 游戏：全局钩子、反作弊、性能和误触风险过高；
- 大量复杂自动化：动作平台竞争激烈，维护成本会吞噬触发体验投入。

## 3. 可持续差异化

单纯的“点划编码”很容易被复制，不能成为护城河。可持续差异化应由四项体验组合形成：

1. **不破坏原生鼠标行为**：采用延迟决策的和弦唤醒；普通点击、拖拽、长按都能可靠放行或补发。
2. **即时提交**：松开引导键立即执行，不等待 750 ms；最短常用节奏在约 500 ms 内完成。
3. **双层学习体验**：熟手盲敲；新手停顿后看到仅与当前输入前缀匹配的候选，而不是打开完整设置页。
4. **上下文复用**：同一个易记节奏在不同应用中触发不同动作，用户只需记“这个位置/节奏代表确认、撤销、静音”等少数语义。

产品语言应从“摩尔斯码工具”转为“Pulse / 节奏快捷键”。摩尔斯码可以用于自动建议，但不应要求用户学习字母表。默认节奏应短、可发音或有语义，例如双击代表切换、短长代表打开、长按代表强操作，并对高风险动作要求二次确认或更长节奏。

## 4. 建议路线图

### 阶段 0：先做价值验证，不扩功能（1 周）

- 访谈 5–8 位鼠标主导用户，让每人选出“每天至少 5 次、无需参数”的 3 个动作；
- 用现有版本或纸面流程测量当前完成时间、误触点和一周后回忆率；
- 输出 3 套场景模板：会议、浏览/办公、设计/创作。

退出条件：找不到至少 5 位愿意连续使用一周、且每人有 3 个明确高频动作的用户，就不进入大规模开发。

### 阶段 1：重做触发可靠性（最高优先级）

- 和弦唤醒、松手提交；
- 原生点击/拖拽/长按的延迟决策与补发；
- Esc/滚轮取消、进程排除、权限窗口放行；
- 本地记录触发耗时、取消、未匹配、误触恢复，不记录具体内容。

验收指标：P50 触发时间 < 600 ms，P95 < 900 ms；误拦截原生鼠标操作 < 0.1%；一周未匹配率 < 10%。

### 阶段 2：解决“记不住”而非增加容量

- 首次只让用户绑定 3 个动作；
- 按动作名称/语义推荐短节奏并检查前缀冲突；
- 犹豫 500–700 ms 后展示当前可选候选；
- 30 秒练习、忘记后提示、每周使用热度；
- 对长期不用的绑定建议归档，而不是鼓励无限新增。

验收指标：第 7 天无需完整列表能正确触发 4/5 个绑定；用户从安装到首次成功动作 < 3 分钟。

### 阶段 3：补齐最小动作原语

只增加能显著扩大前三类场景的动作：发送快捷键、粘贴文本、媒体/音量、窗口操作、系统锁屏；支持调用 URL、程序、脚本和 Quicker 动作 URI。复杂编排继续交给外部工具。

### 阶段 4：应用上下文与模板

- 全局绑定 + 按前台应用覆盖；
- 同一节奏在 Zoom/Teams、浏览器、Excel、设计工具中复用语义；
- 提供可审阅的模板包，但导入前逐项展示动作和权限；
- 在胶囊中明确显示当前场景，防止上下文切换导致误操作。

### 阶段 5：可信分发

- 签名安装包、清晰卸载、更新回滚；
- 公开本地数据与联网边界；
- 诊断页明确说明被排除、权限不足、冲突工具等状态；
- 再考虑自动更新和匿名使用统计，且默认透明、可关闭。

## 5. 未来 8–12 周的取舍

### 应该做

1. 和弦唤醒与原生行为兼容；
2. 即时提交和取消；
3. 三动作 onboarding、犹豫提示、练习；
4. 快捷键/媒体/窗口动作；
5. 按应用覆盖；
6. 5–10 人、连续一周的可用性实验。

### 暂时不做

1. 内置 AI 助手或屏幕理解；
2. 可视化复杂工作流平台；
3. 动作商店/账号/云同步；
4. 移动端或跨平台；
5. 以无限绑定数量作为卖点；
6. 游戏场景。

## 6. 需要验证的关键假设

| 假设 | 最便宜的验证方法 | 通过线 |
|---|---|---|
| 盲敲比菜单更省心 | 同一动作与 Quicker/轮盘做对照计时 | 熟练后中位数快 30% 以上 |
| 用户能记住少量节奏 | 绑定 5 个动作，一周后无提示测试 | 平均正确 ≥ 4/5 |
| 不破坏鼠标原生行为 | 浏览器、Office、资源管理器连续使用 | 误拦截 < 0.1% |
| 使用频率足以形成习惯 | 本地日统计 + 访谈 | 第 7 天人均 ≥ 5 次/日 |
| 上下文复用能降低记忆负担 | 对照全局唯一编码与应用覆盖 | 任务数增加但记忆项不明显增加 |

若使用频率、回忆率或误触指标未达标，应收缩为“方向手势 + 外部动作触发器”，而不是继续增加动作类型。

## 7. 最终判断

PulseMouse 的价值不是覆盖更多动作，而是把极少数高频动作做得比搜索、面板和轨迹手势更“隐形”。如果团队愿意把大部分精力投入输入可靠性、学习曲线和真实留存验证，这个项目有清晰的小众价值，也有成为优秀独立工具的可能。

如果后续仍以新增页面、AI、工作流步骤和视觉效果为主要迭代方向，它会迅速变成 Quicker/Raycast 的弱化版。下一版本的成功标准不应是“又多了多少功能”，而应是：**用户能否在不看屏幕、不移动光标、不误伤原生操作的前提下，每天自然使用至少 5 次。**
